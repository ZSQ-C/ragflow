# 根目录独立文件分析报告

## 一、核心总览（带逻辑关系）

### 核心定位
`rag` 根目录包含三个独立文件：`raptor.py`（RAPTOR 层次摘要处理）、`benchmark.py`（检索性能基准测试）、`settings.py`（模块配置）。核心解决的问题是：如何实现树状结构的递归摘要检索、如何评估检索系统的性能、如何管理模块级别的配置。

### 整体流程串讲
`raptor.py` 从文本块列表开始：UMAP 降维 → GMM 聚类 → 确定最优聚类数 → 为每个聚类生成摘要 → 递归处理直到只剩一个节点。`benchmark.py` 从数据集加载开始：索引文档 → 执行检索 → 计算评估指标 → 保存结果。`settings.py` 作为配置占位文件，实际配置由 `common.settings` 模块管理。

## 二、模块拆分（固定顺序 + 关系说明）

### 1. raptor.py - 初始化模块
**作用**：初始化 RAPTOR 处理器，配置聚类参数和模型。
**位置**：RAPTOR 流程的起点。
**配合关系**：被 task_executor 的 `run_raptor_for_kb` 调用。

```python
class RecursiveAbstractiveProcessing4TreeOrganizedRetrieval:
    def __init__(
        self,
        max_cluster,
        llm_model,
        embd_model,
        prompt,
        max_token=512,
        threshold=0.1,
        max_errors=3,
    ):
        self._max_cluster = max_cluster
        self._llm_model = llm_model
        self._embd_model = embd_model
        self._threshold = threshold
        self._prompt = prompt
        self._max_token = max_token
        self._max_errors = max(1, max_errors)
        self._error_count = 0
```

### 2. raptor.py - 核心入口方法模块
**作用**：执行 RAPTOR 的主流程，递归生成层次摘要。
**位置**：RAPTOR 流程的核心驱动。
**配合关系**：调用 `_get_optimal_clusters` 和 `summarize` 方法。

```python
async def __call__(self, chunks, random_state, callback=None, task_id: str = ""):
    if len(chunks) <= 1:
        return []
    
    chunks = [(s, a) for s, a in chunks if s and a is not None and len(a) > 0]
    layers = [(0, len(chunks))]
    start, end = 0, len(chunks)
    
    while end - start > 1:
        self._check_task_canceled(task_id, "layer processing")
        
        embeddings = [embd for _, embd in chunks[start:end]]
        
        # UMAP 降维
        n_neighbors = int((len(embeddings) - 1) ** 0.8)
        reduced_embeddings = umap.UMAP(
            n_neighbors=max(2, n_neighbors),
            n_components=min(12, len(embeddings) - 2),
            metric="cosine",
        ).fit_transform(embeddings)
        
        # 确定最优聚类数
        n_clusters = self._get_optimal_clusters(reduced_embeddings, random_state, task_id)
        
        # GMM 聚类
        gm = GaussianMixture(n_components=n_clusters, random_state=random_state)
        gm.fit(reduced_embeddings)
        probs = gm.predict_proba(reduced_embeddings)
        lbls = [np.where(prob > self._threshold)[0] for prob in probs]
        
        # 为每个聚类生成摘要
        tasks = []
        for c in range(n_clusters):
            ck_idx = [i + start for i in range(len(lbls)) if lbls[i] == c]
            tasks.append(asyncio.create_task(summarize(ck_idx)))
        
        await asyncio.gather(*tasks)
        
        layers.append((end, len(chunks)))
        start = end
        end = len(chunks)
    
    return chunks
```

### 3. raptor.py - 分支逻辑方法模块
**作用**：确定最优聚类数，使用 BIC 准则评估。
**位置**：在聚类前被调用。
**配合关系**：被 `__call__` 方法调用。

```python
def _get_optimal_clusters(self, embeddings: np.ndarray, random_state: int, task_id: str = ""):
    max_clusters = min(self._max_cluster, len(embeddings))
    n_clusters = np.arange(1, max_clusters)
    bics = []
    
    for n in n_clusters:
        self._check_task_canceled(task_id, "get optimal clusters")
        gm = GaussianMixture(n_components=n, random_state=random_state)
        gm.fit(embeddings)
        bics.append(gm.bic(embeddings))
    
    optimal_clusters = n_clusters[np.argmin(bics)]
    return optimal_clusters
```

### 4. raptor.py - 具体实现方法模块
**作用**：为聚类生成摘要文本和嵌入向量。
**位置**：在聚类后被调用。
**配合关系**：调用 `_chat` 和 `_embedding_encode` 方法。

```python
@timeout(60 * 20)
async def summarize(ck_idx: list[int]):
    self._check_task_canceled(task_id, "summarization")
    
    texts = [chunks[i][0] for i in ck_idx]
    len_per_chunk = int((self._llm_model.max_length - self._max_token) / len(texts))
    cluster_content = "\n".join([truncate(t, max(1, len_per_chunk)) for t in texts])
    
    try:
        async with chat_limiter:
            self._check_task_canceled(task_id, "before LLM call")
            
            cnt = await self._chat(
                "You're a helpful assistant.",
                [{"role": "user", "content": self._prompt.format(cluster_content=cluster_content)}],
                {"max_tokens": max(self._max_token, 512)}
            )
            
            self._check_task_canceled(task_id, "before embedding")
            
            embds = await self._embedding_encode(cnt)
            chunks.append((cnt, embds))
    except TaskCanceledException:
        raise
    except Exception as exc:
        self._error_count += 1
        if self._error_count >= self._max_errors:
            raise RuntimeError(f"RAPTOR aborted after {self._error_count} errors")
```

## 三、方法详细解析（强制 5 要素 + 文字流程串讲）

### `RecursiveAbstractiveProcessing4TreeOrganizedRetrieval.__call__` 方法

**文字流程串讲**：
方法首先检查输入块数量，若小于等于 1 则返回空列表。过滤掉空内容和空向量的块。初始化层记录列表，记录当前处理的起始和结束位置。进入主循环，当剩余块数大于 1 时继续处理。首先检查任务是否被取消。提取当前层所有块的嵌入向量。计算 UMAP 降维参数：邻居数为块数的 0.8 次方，维度数取 12 和块数减 2 的较小值。执行 UMAP 降维，使用余弦距离度量。调用 `_get_optimal_clusters` 确定 BIC 最小的聚类数。若聚类数为 1，则所有块属于同一聚类；否则使用 GMM 进行软聚类，根据阈值确定每个块所属的聚类。为每个聚类创建摘要任务，并发执行。更新层记录，移动起始和结束位置。循环结束后返回包含所有原始块和摘要块的列表。

**强制 5 要素**：
| 要素 | 内容 |
|------|------|
| 入参 | `chunks: list[tuple[str, np.ndarray]]`（必填，文本和向量对）；`random_state: int`（必填）；`callback: Callable`（选填）；`task_id: str`（选填） |
| 核心逻辑 | UMAP 降维 → GMM 聚类 → 摘要生成 → 递归处理 |
| 输出形式 | `list[tuple[str, np.ndarray]]`，原始块和摘要块的合并列表 |
| 底层关键依赖 | `umap.UMAP`（降维）；`sklearn.mixture.GaussianMixture`（聚类）；`asyncio.gather`（并发） |
| 关键代码片段 | `reduced_embeddings = umap.UMAP(n_neighbors=max(2, n_neighbors), n_components=min(12, len(embeddings) - 2), metric="cosine").fit_transform(embeddings)` |

---

### `_get_optimal_clusters` 方法

**文字流程串讲**：
方法首先计算最大聚类数，取配置值和嵌入数量的较小值。生成从 1 到最大聚类数的数组。初始化 BIC 值列表。遍历每个候选聚类数，首先检查任务是否被取消。创建 GMM 模型实例，设置随机种子确保可重复性。拟合嵌入数据，计算 BIC 值并添加到列表。BIC（贝叶斯信息准则）越小表示模型越好，同时考虑了模型复杂度的惩罚。遍历完成后，返回 BIC 最小值对应的聚类数。

**强制 5 要素**：
| 要素 | 内容 |
|------|------|
| 入参 | `embeddings: np.ndarray`（必填）；`random_state: int`（必填）；`task_id: str`（选填） |
| 核心逻辑 | 遍历聚类数 → GMM 拟合 → BIC 计算 → 选择最优 |
| 输出形式 | `int`，最优聚类数 |
| 底层关键依赖 | `sklearn.mixture.GaussianMixture`（聚类模型）；`gm.bic()`（BIC 计算） |
| 关键代码片段 | `optimal_clusters = n_clusters[np.argmin(bics)]` |

---

### `summarize` 内部函数

**文字流程串讲**：
函数首先检查任务是否被取消。提取聚类中所有块的文本内容。计算每个块的最大长度，确保总长度不超过模型限制。将所有文本用换行符连接，使用 truncate 函数截断超长文本。尝试获取 chat_limiter 信号量，限制并发 LLM 调用。再次检查任务是否被取消。调用 `_chat` 方法生成摘要，传入系统提示、用户消息和生成配置。处理返回结果，去除截断提示。检查任务是否被取消。调用 `_embedding_encode` 为摘要生成嵌入向量。将摘要文本和向量添加到 chunks 列表末尾。若发生 TaskCanceledException 则向上抛出。若发生其他异常，增加错误计数，若达到最大错误数则抛出 RuntimeError。

**强制 5 要素**：
| 要素 | 内容 |
|------|------|
| 入参 | `ck_idx: list[int]`（必填，块索引列表） |
| 核心逻辑 | 文本拼接 → LLM 摘要 → 向量生成 → 结果追加 |
| 输出形式 | 无返回值，结果追加到 chunks 列表 |
| 底层关键依赖 | `self._chat()`（LLM 调用）；`self._embedding_encode()`（向量生成）；`chat_limiter`（并发控制） |
| 关键代码片段 | `chunks.append((cnt, embds))` |

### `Benchmark.ms_marco_index` 方法

**文字流程串讲**：
方法初始化 qrels 字典（查询到文档相关性）和 texts 字典（文档 ID 到文本）。遍历数据集目录中的所有 parquet 文件。对每个文件，使用 pandas 读取数据。遍历每行数据，提取查询和段落列表。对于每个段落，创建文档字典，包含 ID、知识库 ID、文档名等字段。调用 `tokenize` 函数对文本进行分词和词项权重计算。将文档添加到批次列表，记录文本和相关性标签。当批次达到 32 个文档时，调用 `embedding` 方法生成向量，初始化索引（若尚未初始化），调用 `docStoreConn.insert` 写入索引。清空批次列表继续处理。文件处理完成后，对剩余文档执行同样的操作。返回 qrels 和 texts 字典。

| 输出形式 | `tuple[dict, dict]`，qrels 和 texts 字典 |
| 底层关键依赖 | `pd.read_parquet()`（数据读取）；`tokenize()`（分词）；`self.embedding()`（向量化）；`settings.docStoreConn.insert()`（索引写入） |
| 关键代码片段 | `qrels[query][d["id"]] = int(rel)` |

## 五、疑惑解答

**Q1: RAPTOR 为什么使用 GMM 而不是 K-Means 聚类？**
A: GMM（高斯混合模型）支持软聚类，每个点可以以不同概率属于多个聚类。RAPTOR 使用阈值（threshold=0.1）来确定归属，这样可以处理边界模糊的情况。K-Means 只支持硬聚类，无法表达这种不确定性。

**Q2: 为什么 UMAP 的 n_neighbors 参数使用 0.8 次方？**
A: 0.8 次方是一个经验值，使得邻居数随数据量增长但增速递减。这样可以在小数据集上保持足够的局部结构，在大数据集上避免过度平滑。具体值可以根据实际数据特性调整。

**Q3: Benchmark 为什么使用 NDCG、MAP、MRR 三个指标？**
A: 这三个指标从不同角度评估检索质量：NDCG 考虑排序位置的相关性权重；MAP 关注所有相关文档的平均排名；MRR 只关注第一个相关文档的排名。综合使用可以全面评估系统性能。
